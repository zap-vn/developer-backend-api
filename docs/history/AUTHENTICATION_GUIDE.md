# 401 Unauthorized Error - Solution Guide

## Problem Summary
You're getting a **401 Unauthorized** error when accessing protected API endpoints like `/api/Data/Product/ProductS?F4021`.

## Root Cause
The `DataController` (and most other controllers) inherit from `BaseApiController` which has the `[Authorize]` attribute. This means **all endpoints require a valid JWT token** for authentication.

## Solution Steps

### Option 1: Using PowerShell Script (Recommended for Windows)

1. **Update credentials** in `test_login.ps1`:
   ```powershell
   $loginRequest = @{
       UserName = "your-actual-email@example.com"
       Password = "your-actual-password"
       MerchantName = "your-merchant-name"
       IsRemember = $false
   }
   ```

2. **Run the script**:
   ```powershell
   .\test_login.ps1
   ```

3. **Copy the token** from the output and use it in your API requests.

### Option 2: Using Postman/REST Client

#### Step 1: Login to Get Token

**Request:**
```http
POST http://localhost:5271/api/Auth/login
Content-Type: application/json

{
  "UserName": "your-email@example.com",
  "Password": "your-password",
  "MerchantName": "your-merchant-name",
  "IsRemember": false
}
```

**Expected Response:**
```json
{
  "Success": true,
  "Message": "Login successful",
  "MerchantName": "your-merchant-name",
  "AccessToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "Avatar": "...",
  "ExpiresIn": 3600,
  "FullName": "John Doe",
  "RefreshToken": "...",
  "Role": "Owner (Super Admin)",
  "UserGuid": "Customer/12345"
}
```

#### Step 2: Use the Token in Your Requests

Copy the `AccessToken` value and add it to your Authorization header:

**Request:**
```http
GET http://localhost:5271/api/Data/Product/ProductS?F4021
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

### Option 3: Using cURL

```bash
# Step 1: Login
curl -X POST http://localhost:5271/api/Auth/login \
  -H "Content-Type: application/json" \
  -d '{
    "UserName": "your-email@example.com",
    "Password": "your-password",
    "MerchantName": "your-merchant-name",
    "IsRemember": false
  }'

# Step 2: Use the token (replace <TOKEN> with actual token)
curl -X GET "http://localhost:5271/api/Data/Product/ProductS?F4021" \
  -H "Authorization: Bearer <TOKEN>"
```

## What Was Fixed

### 1. **AuthService Token Generation**
Changed from hardcoded issuer/audience to use configuration values:

**Before:**
```csharp
issuer: "https://dev-crm-merchant-api.diadiem.vn",
audience: "tranvuong MJ",
```

**After:**
```csharp
issuer: _jwtSettings.Issuer,
audience: _jwtSettings.Audience,
```

This ensures the token generation matches the configuration in `appsettings.json`.

## Understanding the Authentication Flow

1. **User sends credentials** → `POST /api/Auth/login`
2. **AuthService validates** password and user status
3. **JWT token is generated** with claims (UserGuid, Email, Role, etc.)
4. **Token is returned** to the user
5. **User includes token** in subsequent requests via `Authorization: Bearer <token>` header
6. **API validates token** and extracts claims
7. **BaseApiController** reads `UserGuid` from claims
8. **Request proceeds** with user context

## Common Issues

### Issue 1: "Invalid credentials"
- Check that the username (email) is correct
- Check that the password matches what's in the database
- Verify the merchant name is correct

### Issue 2: "Account is not active"
- The customer account must have `CustomerStatusId = 1` and `Visible = 1`

### Issue 3: "Missing UserGuid claim"
- The token must be generated by the login endpoint
- The token must not be expired
- The token must be properly formatted in the header: `Bearer <token>`

### Issue 4: Token expired
- Default token lifetime is 60 minutes (or 1440 minutes if `IsRemember = true`)
- Login again to get a fresh token

## Debugging Tips

1. **Check if API is running**:
   ```powershell
   curl http://localhost:5271/swagger
   ```

2. **Check MongoDB connection**:
   - Verify MongoDB is running at `mongodb://172.16.10.153:27017`
   - Check if `SinglePoint_en` database exists

3. **View application logs**:
   - Look for `"Login attempt for user:"` messages
   - Check for authentication errors

4. **Decode your JWT token**:
   - Visit https://jwt.io
   - Paste your token to see claims and expiration

## Security Notes

⚠️ **Important for Production:**
1. Use HTTPS in production (currently `RequireHttpsMetadata = false` for development)
2. Store JWT secret in environment variables or Azure Key Vault
3. Don't expose stack traces in error responses
4. Implement refresh token rotation
5. Add rate limiting for login attempts
