## Why It's Failing (401 Unauthorized)

Your token was generated by an **external/legacy system** with a specific JWT secret key. The current API is configured with a different secret:

```json
"Secret": "your-super-secret-key-that-should-be-at-least-32-characters-long"
```

JWT tokens are **cryptographically signed** using the secret. If the API uses a different secret to validate the token, the signature verification fails, resulting in a 401 error.

## Solutions

### Option 1: Generate a New Token (RECOMMENDED)

Login through THIS API to get a new token signed with the current secret:

1. **Make sure the API is running**:
   ```powershell
   cd services\Zap.Identity.Api
   dotnet run
   ```

2. **Update and run the login script**:
   - Open `quick_login.ps1`
   - Update the password and merchant name
   - Run: `.\quick_login.ps1`

3. **Use the new token** in your requests

### Option 2: Find and Use the Legacy JWT Secret

If you have access to the legacy system's configuration:

1. **Find the JWT secret** from the legacy system
   - Check the configuration files
   - Contact the system administrator

2. **Update `appsettings.json`**:
   ```json
   "JwtSettings": {
     "Secret": "<legacy-secret-here>",
     ...
   }
   ```

3. **Restart the API** for changes to take effect

4. **Your existing token will now work**!

### Option 3: Disable Signature Validation (NOT RECOMMENDED - DEV ONLY)

⚠️ **WARNING**: Only for local development/testing. NEVER use in production!

Modify `Program.cs` to skip signature validation:
```csharp
options.TokenValidationParameters = new TokenValidationParameters
{
    ValidateIssuerSigningKey = false,  // <-- Disable validation
    ValidateIssuer = false,
    ValidateAudience = false,
    ValidateLifetime = true,
    // ... rest of config
};
```
